# A7-02 — Persistent branches and trusted activation

Execute only when explicitly selected. Apply [CONTRACT.md](CONTRACT.md), including verification limits. Prerequisite: accepted A7-01 contracts and feasibility evidence.

## Deliverable

Implement durable village/branch plans, progress and bounded diagnostics, plus recoverable hardware activation through existing policy/journal services. No production village generator, wider kiosk or banker entity belongs to this package.

- Append migrations using the actual current registry; preserve historical definitions and integrate schema validation, journal replay, offline inspection and backup compatibility as affected.
- Persist captured counts/choices/revisions, stable branch slots, institution/native currency, placement/service anchors and explicit pending/conflict/removal history. Apply required-provider readiness and optional-provider omission separately from terrain pending.
- Implement internal server-only bootstrap authority scoped to branch/anchor/generation and expected revisions. Reuse existing terminal placement/binding and custody protections. No arbitrary operator authority, customer account or capital creation.
- Resolve original operation outcomes after uncertain commits. Cross-effect recovery must distinguish planned, placing, hardware-pending and active branches from dismantled ones; never rebuild player removals.
- Provide bounded operator branch/status inspection and the contracted safe retry interface. Terrain-pending retries require explicit operator action, retain captured choices and fresh site checks; physical placement implementation remains with A7-04.
- Expose detached server-side contracts for later generation, kiosks and staffing; no client-created authoritative branch IDs/proofs.

## Acceptance and stop

Demonstrate durable identity/idempotent activation and no change to accounts/capital under relevant replay/removal paths. Prefer existing real-service/SQLite fixtures; choose at most one focused invocation for changed persistence/activation invariants if useful. Do not run whole packages or full suites automatically. Run ordinary runnable delivery checks once. Update current branch architecture and handoff, recording the generator adapter still absent. Stop before A7-03.
